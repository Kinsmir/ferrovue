Upgrading a project from ferrovue 0.15 to 0.16: the steps to take and what behaves differently.

The [CHANGELOG](https://github.com/Kinsmir/ferrovue/blob/main/CHANGELOG.md) lists every change;
this page picks out what an application notices. The steps are to bump both halves together and to
generate every component again, for version 9 of generated code. A page renders the same HTML as
with 0.15, in fewer instructions. An upgrade to 0.15 took only the bump, so the page for the
release before is [`upgrading_to_0_14`](crate::guide::upgrading_to_0_14).

# Steps

## 1. Bump both halves together

The npm package and the crates are released together at one version, and generated code works with
the crate of its own release. Bump the npm package:

```sh
pnpm add -D ferrovue@^0.16.0
```

and the crate, in `Cargo.toml`:

```toml
ferrovue = "0.16"
```

`ferrovue` depends on `ferrovue-core`, `ferrovue-router` and `ferrovue-i18n` at exactly its own
version, so an application that names only `ferrovue` gets the other three with it. One that names
any of them itself bumps it to 0.16 as well. A project that lists `ferrovue@0.15.2` in pnpm's
`minimumReleaseAgeExclude` adds `ferrovue@0.16.0` beside it, and removes the 0.15.2 entry once the
lockfile no longer holds it.

## 2. Generate every component again

```sh
pnpm ferrovue
```

The 0.16 compiler writes version 9 of generated code, and `mod.rs` opens with
`ferrovue::__compat!(9)`. Version 9 writes the string a list's `.join()` builds straight into the
page, item by item, with helpers the 0.15 crate lacks. The 0.16 crate supports versions 6 to 9, so
a module generated by 0.15 still builds against it. The 0.15 crate stops a module of version 9 at
its first line:

```text
error: this module was generated as version 9 of ferrovue's generated code, and this `ferrovue` crate supports versions 6 to 8: use the `ferrovue` npm package and the `ferrovue` crate of one release, and run `ferrovue` to generate the module again
```

Most generated files change once. A render writes the text beside a `v-if` or `?:` inside each
branch, writes text that needs no escaping without `escape_into`, and the modules lose their stray
blank lines. A module imports `std::borrow::Cow` and writes `Cow`, and a field keeps
`#[serde(rename)]` only where its JSON key differs from its name, so props read and write the same
JSON. What a render writes is the same. A CI job that runs `pnpm ferrovue --check` reports each
module as stale until it is generated again with 0.16 and committed. See
[the version check](crate::guide::generated_code#the-version-check).

# Behaviour that changed

## Renders run fewer instructions

The HTML of every page is byte for byte what 0.15 wrote. `escape_into` escapes in one pass, which
helps most on long strings, and a `.join()` writes into the page with no string built per item.
The bench renders run up to 9% fewer instructions, and renders that join a list up to 25% fewer.
A test that counts allocations or instructions of a render sees lower numbers. See
[how a render writes text](crate::guide::generated_code#how-a-render-writes-text).
