vue-i18n's `$t` and `useI18n()`, rendered in the reader's locale.

The translations are the `ferrovue-i18n` crate, which ferrovue re-exports as
[`ferrovue::i18n`](crate::i18n) with the `i18n` feature. The feature is on by default; generated
code needs it once the project configures `i18n`.

# Configuring

Point `i18n` at the directory of locale files, one JSON file per locale, and name the default and
fallback locales:

```json
{ "i18n": { "messages": "client/locales", "locale": "en", "fallbackLocale": "en" } }
```

```json
{ "greeting": "Hello {name}!", "apples": "no apples | one apple | {count} apples", "common": { "app": "ferrovue" } }
```

The compiler parses every message with vue-i18n's own message compiler, at build time, and writes
the result to `i18n.rs` as static tables. Nothing is parsed at run time.

# The generated module

```rust
# mod i18n {
// @generated by ferrovue from locales/. Do not edit: change the locale files and run
// `ferrovue`.

//! The messages of every locale, compiled by vue-i18n's own message compiler.

use ferrovue::i18n::{Locale, Message, Part};

/// The locale a page renders in when it names none.
pub const LOCALE: &str = "en";

/// The locales a missing message falls back to, in order.
pub const FALLBACK: &[&str] = &["en"];

/// Every locale's messages.
pub static LOCALES: &[Locale] = &[
    Locale {
        name: "en",
        messages: &[
            ("apples", Message { cases: &[&[Part::Text("no apples")], &[Part::Text("one apple")], &[Part::Named("count"), Part::Text(" apples")]] }),
            ("common.app", Message { cases: &[&[Part::Text("ferrovue")]] }),
            ("greeting", Message { cases: &[&[Part::Text("Hello "), Part::Named("name"), Part::Text("!")]] }),
        ],
    },
    Locale {
        name: "nl",
        messages: &[
            ("apples", Message { cases: &[&[Part::Text("geen appels")], &[Part::Text("één appel")], &[Part::Named("count"), Part::Text(" appels")]] }),
            ("greeting", Message { cases: &[&[Part::Text("Hallo "), Part::Named("name"), Part::Text("!")]] }),
        ],
    },
];

/// The messages in `locale`, with the configured fallbacks: build one per request.
pub fn i18n(locale: &str) -> ferrovue::I18n {
    ferrovue::I18n::new(LOCALES, locale, FALLBACK)
}
# }
# let _ = i18n::i18n(i18n::LOCALE);
```

(Messages are listed by key, nested keys joined with dots and sorted, so that lookup is a binary
search.)

# Rendering in a locale

Choose the locale per request, from the URL, a cookie or `Accept-Language`, build an
[`I18n`](crate::I18n) with the generated `i18n(locale)`, and pass it to every component that
translates. It comes after the props, the slots, the route and the stores in `render`'s parameters.

```vue
<!-- Translated.vue -->
<script setup lang="ts">
import { useI18n } from "vue-i18n";
defineProps<{ name: string; count: number }>();
const { locale } = useI18n();
</script>

<template>
  <p :lang="locale">{{ $t("greeting", { name }) }} {{ $t("apples", count) }} {{ $t("common.app") }}</p>
</template>
```

Each `$t` is a call of [`I18n::t`](crate::I18n::t) with an [`Args`](crate::i18n::Args), and its
result is escaped like any other interpolation.

# What is supported

Named (`{name}`) and list (`{0}`) values, plurals chosen by vue-i18n's default rule
(`t("apples", count)`, or a `count` or `n` value), literals (`{'{'}`), linked messages (`@:key`)
with the `upper`, `lower` and `capitalize` modifiers, nested and flat keys, fallback locales in
order, and a missing key, which renders as the key itself, as vue-i18n does. `useI18n()`'s `locale`
reads [`I18n::locale`](crate::I18n::locale).

The plural case is chosen as vue-i18n chooses it, from a `count` or `n` value that is a finite
number, else from the plural number. A fractional `count` (a `Float`) is kept as it is: with two
cases, only exactly `1` is singular, so `1.5` is plural; with three, `0` is the first, `1` the
second, and `2` or more the third. A `count` that is `NaN` or infinite is passed over for the
plural number. A fraction below 2 chooses none of three cases, which makes vue-i18n throw; a debug
build's render panics there too, and a release build writes nothing for the message.

A translated message is text: it is escaped when written, so a message holding `<b>` shows the tag
as text, as `{{ $t(…) }}` does in Vue. `v-html` of a message is refused, as `v-html` of anything but
a `TrustedHtml` prop is.

On the client, give vue-i18n the same locale files and the locale the server rendered in, or the
hydrated text will differ.
